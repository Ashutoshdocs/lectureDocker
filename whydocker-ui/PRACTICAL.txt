========================================
UI-BASED PRACTICAL: WHY DOCKER
One VM  ->  one Java page the old way,
            two Java pages with Docker.
========================================
Goal:
Run a browser dashboard on your VM. From the
dashboard you SWITCH the machine's single Java
runtime (only ONE app page can be live at a
time). Then you use Docker to run BOTH Java
versions as containers AT THE SAME TIME (two
pages live together).

This is the visual, clickable version of the
two CLI practicals.

----------------------------------------
FILES IN THIS PRACTICAL
----------------------------------------
Server.java        one small web app; prints the
                   ACTUAL Java runtime on a web page
control.py         the dashboard backend (Python,
                   standard library only)
dashboard.html     the control panel UI
Dockerfile.java8   image locked to Java 8
Dockerfile.java17  image locked to Java 17

----------------------------------------
PORTS USED (open these on the VM)
----------------------------------------
9000  dashboard (the control panel)
8080  the single VM app page
8081  Docker container -> Java 8 page
8082  Docker container -> Java 17 page

On Azure: add inbound rules for 9000, 8080,
8081, 8082 in the VM's Network Security Group.
On the VM firewall (if enabled):
  sudo ufw allow 9000
  sudo ufw allow 8080
  sudo ufw allow 8081
  sudo ufw allow 8082

----------------------------------------
STEP 0: Prerequisites
----------------------------------------
Commands:
sudo apt update
sudo apt install openjdk-8-jdk openjdk-17-jdk -y
docker --version
python3 --version

Explanation:
Both JDKs are needed for the VM switch demo.
Docker is needed for the two-containers demo.
Python 3 runs the dashboard (no pip installs).

----------------------------------------
STEP 1: Put the files on the VM
----------------------------------------
Commands:
cd /home/azure
mkdir why-docker-ui && cd why-docker-ui
# copy Server.java, control.py, dashboard.html,
# Dockerfile.java8, Dockerfile.java17 into here

Explanation:
Keep all five files in one folder. control.py
serves dashboard.html from the same folder.

----------------------------------------
STEP 2: Start the dashboard
----------------------------------------
Command:
python3 control.py

Expected output:
 JDK 8   : /usr/lib/jvm/java-8-openjdk-amd64
 JDK 17  : /usr/lib/jvm/java-17-openjdk-amd64
 Docker  : yes
 compile : Server.class ready
 Open the dashboard:  http://<this-vm-ip>:9000

Explanation:
On startup it auto-detects both JDKs and Docker,
compiles Server.java, and starts the control
panel. If a JDK isn't found, set it manually:
  JAVA8_HOME=/path/to/jdk8 \
  JAVA17_HOME=/path/to/jdk17 python3 control.py

----------------------------------------
STEP 3: Open the dashboard in a browser
----------------------------------------
Open:
http://<your-vm-public-ip>:9000

Explanation:
Top of the page shows three status chips:
JDK 8 / JDK 17 / Docker. All three should read
"ready". Left half = the VM way. Right half =
the Docker way.

========================================
PART A  --  THE VM WAY (only ONE page)
========================================

----------------------------------------
STEP 4: Run the app on Java 8
----------------------------------------
Click:
"Run app on Java 8"  (left panel)

Result:
The preview under it goes LIVE and shows:
   Running with Java version: 1.8.0_xxx
   On the host VM  |  port 8080
You can also open http://<vm-ip>:8080 directly.

Explanation:
The dashboard launched ONE JVM (Java 8) on the
single runtime slot at port 8080.

----------------------------------------
STEP 5: Now switch to Java 17
----------------------------------------
Click:
"Run app on Java 17"  (left panel)

Result:
The SAME single preview now shows:
   Running with Java version: 17.0.xxx
The Java 8 app is GONE. There is still only ONE
page at port 8080.

Explanation (the whole point of Part A):
The VM has one system runtime slot. Starting
Java 17 STOPPED Java 8 first. You can never see
both pages at once here -- exactly like a VM
where only one Java version is active at a time.
Switching one app forces the other to give up.

----------------------------------------
STEP 6 (optional): Stop
----------------------------------------
Click:
"Stop"  (left panel)

Result:
The preview goes empty. No app is running.

========================================
PART B  --  THE DOCKER WAY (BOTH pages)
========================================

----------------------------------------
STEP 7: Build both images
----------------------------------------
Click:
"Build both images"  (right panel)

Result (after a short wait):
"Both images built: app-java8, app-java17."

Explanation:
Each image bakes in its OWN Java version:
  Dockerfile.java8  -> eclipse-temurin:8-jdk
  Dockerfile.java17 -> eclipse-temurin:17-jdk
The host VM's Java version does not matter here.

----------------------------------------
STEP 8: Run BOTH containers at once
----------------------------------------
Click:
"Run both containers"  (right panel)

Result:
TWO previews go LIVE at the SAME TIME:
  port 8081 -> Running with Java version: 1.8.0_xxx
              Inside a Docker container
  port 8082 -> Running with Java version: 17.0.xxx
              Inside a Docker container

Explanation (the whole point of Part B):
Two different Java runtimes are serving two live
pages simultaneously, on one VM, with no
switching and no conflict. This is the thing the
VM half could not do.

----------------------------------------
STEP 9 (optional): Prove it from the CLI too
----------------------------------------
Commands:
docker ps
docker exec -it java8-container  java -version
docker exec -it java17-container java -version

Explanation:
Both containers are Up at once and each answers
with its own JVM version.

----------------------------------------
STEP 10 (optional): Stop
----------------------------------------
Click:
"Stop"  (right panel)   [removes both containers]

========================================
SIDE-BY-SIDE, ON THE SAME SCREEN
========================================
VM panel:
  - one runtime slot, one page on 8080
  - switching Java 8 <-> Java 17 replaces the page
  - only ONE version live at any moment

Docker panel:
  - two containers, two pages on 8081 + 8082
  - Java 8 and Java 17 live together
  - no switching, no conflict

----------------------------------------
FINAL CONCLUSION
----------------------------------------
On a plain VM, Java is a single shared runtime:
one version at a time, and switching it takes the
other app down with it.

With Docker, each app carries its own runtime in
its own container, so multiple Java versions run
side by side on the same machine.

THIS IS WHY DOCKER IS USED IN PRODUCTION.
========================================
